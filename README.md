# Hackaton

Base de trabajo para desarrollar el proyecto del hackatón.

> Estado: preparación. La idea, las tecnologías y el producto mínimo viable (MVP) están pendientes de definición. Todavía no hay una aplicación ejecutable.

## Por dónde empezar

1. Completar [el alcance](docs/ALCANCE.md): problema, usuarios y resultado esperado.
2. Priorizar las tareas del [roadmap](docs/ROADMAP.md).
3. Registrar las tecnologías y decisiones en [arquitectura](docs/ARQUITECTURA.md).
4. Implementar una primera funcionalidad completa en `src/` y sus pruebas en `tests/`.
5. Preparar la demostración siguiendo [la guía de demo](docs/DEMO.md).

## Estructura

| Ruta | Contenido |
| --- | --- |
| `src/` | Código de la aplicación, organizado por funcionalidad |
| `tests/` | Pruebas automatizadas y escenarios de aceptación |
| `docs/` | Alcance, arquitectura, roadmap y demostración |
| `scripts/` | Automatizaciones de desarrollo |
| `assets/` | Recursos gráficos y materiales del proyecto |
| `.github/` | Plantillas de tareas, errores y pull requests |

## Desarrollo

Consulta [CONTRIBUTING.md](CONTRIBUTING.md). Usa ramas cortas y pull requests con cambios verificables. Los comandos de instalación, ejecución y pruebas se añadirán al elegir las tecnologías.

## Configuración

No subir contraseñas, tokens ni archivos `.env`. Cuando la aplicación requiera variables, documentar sus nombres con valores ficticios en `.env.example`.
